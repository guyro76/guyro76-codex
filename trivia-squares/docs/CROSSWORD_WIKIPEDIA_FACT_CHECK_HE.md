# מנוע חידונאי: ויקיפדיה + Wikidata

## מטרת הפיתוח

לבנות מאגר טריוויה עשיר ולא סתם לצבור אלפי שאלות גאוגרפיה. כל עובדה אמיתית היא חומר גלם לשאלה אחת בלבד בכל שפה. נושאים מנוהלים כמו בתכנון תשבץ או חידון טלוויזיה, כולל איזון בין נושאים ורמות קושי. תוצאה חייבת להציע ארבע תשובות מובחנות ולציין מקור שניתן לפתוח ולבדוק.

המנוע הוסף לקוד בפרויקט, ללא API בתשלום, ללא שירות AI חיצוני וללא העברה אוטומטית של שאלות לא מאושרות אל המשחק.

## 30 קטגוריות

הרשימה המלאה, כולל שמות בעברית, אנגלית, רוסית, צרפתית וערבית: [crossword-topics.mjs](../scripts/crossword-topics.mjs).

כיסוי: פוליטיקה ישראלית ועולמית; היסטוריה ישראלית ועולמית; סדרות ישראליות ועולמיות; קולנוע ישראלי ועולמי; מוזיקה ישראלית ועולמית; ספרים וסופרים; שירה; אמנות; אדריכלות; גאוגרפיה; מדע; חלל; טבע; טכנולוגיה; המצאות; ספורט; כדורגל; אולימפיאדות; אוכל; שפות; מסורות; תכני ילדים; אנשים מפורסמים; פרסי נובל; חידות רמזים בסגנון תשחץ.

19 משפחות עובדות מובְנות ניתנות לחיפוש אוטומטי: בירות, מטבעות, במאים, תסריטאים, מקור של סרטים, יוצרי סדרות, מחברי ספרים, זמרים ומבצעי שירים, ציירים, פסלים, אדריכלים, מייסדי חברות, מקומות לידה ועוד. משפחות נוספות דורשות הנדסת מקור ועריכת תוכן; אין לייצר עובדות לא ניתנות לאימות.

## איך בונים שאלה?

1. **רעיון חידונאי**: בוחרים תחום ותת-נושא, קהל יעד, קושי ויחס רמז/ידע. רמזים אפשריים: זיהוי היוצר, מי כתב, מה שם הבירה, מה מקור הסרט, איזה אדם קשור ליצירה, קשרי אישיות ומקום. כל רמז צריך להוביל לתשובה חד-משמעית, ולא להסתמך על ניסוח מטעה.
2. **איתור**: מבצעים שאילתת SPARQL מדודה ב-Wikidata (למשל סרט מסוג Q11424 ומאפיין במאי P57).
3. **הוכחה ראשונה**: מורידים את ישות המקור באמצעות API ומוודאים שהמאפיין מחזיק בדיוק ערך פעיל אחד. שאלה עם מספר במאים/מחברים אינה מונפקת במתכונת המנוסחת ביחיד.
4. **הוכחה שנייה**: מוצאים קישור Wikipedia מתוך אותה ישות, מאמתים את מזהה Wikidata של הערך ומחפשים את שם התשובה בפסקת הפתיחה בוויקיפדיה באנגלית. שומרים קישור ומזהה גרסת עמוד. **חשוב:** התאמת שם בפסקת הפתיחה היא *סינון ראיות*, לא הוכחה סמנטית מלאה; עדיין נדרשת בקרת עריכה.
5. **מסיחים הגיוניים**: שלושת השמות האחרים מגיעים רק מישויות אחרות באותה משפחת עובדות, לא משמות שהומצאו. מוודאים ארבע אפשרויות שונות ושאין תשובה נכונה נוספת.
6. **חמש שפות יחד**: אם אין שמות Wikidata אמיתיים גם בעברית, באנגלית, ברוסית, בצרפתית ובערבית, נפסלת כל חבילת השאלה. אין תרגום אוטומטי סמוי ואין שימוש במזהים Q123 בתור תשובה.
7. **ניסוח חידונאי**: בוחרים לפי מזהה העובדה ניסוח אחד מבין כמה סגנונות, בלי להדפיס עשר שאלות זהות על אותה עובדה.
8. **בקרת איכות**: מניעת כפילויות, שמירת מקור/גרסה, בדיקת מספר תשובות, הימנעות משאלות רגישות לזמן ללא תאריך, איזון קטגוריות, ואישור אנושי לניסוחים שבספק. שאלות פוליטיקה מתעדכנות וצריכות הקשר זמן.
9. **פרסום לאחר סקירה**: קובץ מועמדים בלבד. כל שאלה מסומנת pending_review. רק לאחר אישור אפשר להעבירה למאגר השאלות המאושרות.

## הרצה ללא עלות

מהתיקייה trivia-squares בריפו (Node.js 24):

    node --test tests/crossword-generator.test.mjs

ליצירת אצווה לבדיקה:

    node scripts/generate-crossword-trivia.mjs --topics film-director,novel-author,painting-artist,israel-politician-birthplace --limit 30 --out ./trivia-review-2026.json

לרשימה מלאה של משפחות הנתמכות:

    node scripts/generate-crossword-trivia.mjs --help

המנוע משתמש ב-Wikidata Query Service, ב-Wikidata Action API וב-Wikipedia Action API דרך HTTPS, בכמויות קטנות ועם User-Agent מזוהה. אם מקור אינו זמין, ההרצה נכשלת ולא מייצרת תשובה מומצאת. אין הרצה מתוך הדפדפן, אין מפתח מנהל שמוטמע באתר, ואין כתיבה ישירה לבסיס הנתונים.

## איזון בין נושאים

בעיית המאגר הנוכחי: יותר מ-5,200 פריטים גאוגרפיים בכל אחת מהשפות ורק עשרות בנושאים האחרים. ההגדלה המספרית לבדה אינה איכות. בתכנון האוצרות יש להגביל גאוגרפיה לרוב ל-10–15 אחוז ממחזור שאלות ולהקצות את השאר לסדרות, סרטים, מוזיקה, היסטוריה, פוליטיקה, מדע ועוד. לבחור איזון גם בין דרגות קושי ובין סגנונות רמזים, בלי לפגוע בשאלות שכבר נראו לשחקן.

מנגנון חיפוש זה מייצר מועמדים מגוונים עם ראיות, אך **אינו מאשר ש-5,000 שאלות חידונאיות אכן אומתו**. לפני ייבוא נדרש לעבור על ערכי המקור, איכות המסיחים, העקביות הרב-לשונית וזכויות השימוש. מטא-נתוני Wikidata זמינים בתנאי CC0; אין להעתיק את פסקת הוויקיפדיה אלא לשמור קישור ומספר גרסה לצורכי אימות.
